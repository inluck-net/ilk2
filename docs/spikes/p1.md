## Q1: dispatch layer

**Recommendation (judgment call): the CLI, for M1 and onward; do not adopt the Agent SDK now.** The SDK passed every criterion (MiMo, session identity on resume, hook parity, cancel by process group, timing metrics, sandbox), but only behind the same wrapper the CLI needs:
- it spawns the CLI in the caller's process group, so a group kill would also kill the driver (`claude_agent_sdk/_internal/transport/subprocess_cli.py:873-881`);
- it passes the whole inherited environment, and `options.env` cannot remove keys (`:819-825`);
- it bundles its own CLI (2.1.294 against 2.1.296 installed, 212 MB);
- it makes an extra model call per session for a title.

What it adds (typed messages, in-process hook callbacks) is small next to file hooks, which already work. Wrong if M1+ needs in-process control requests (interrupt, permission prompts) that the CLI cannot give.

**Verdict: adopt preloading** (`ProjectConfig.preload` now defaults to true). Q10's rule was "adopt only if total minutes per accepted step fall without lower acceptance or more repair attempts": minutes fell 24%, acceptance was equal, and attempts fell. Judgment call: 4 of 4 paired steps favour P, which on a sign test is p = 0.125 two-sided, so this is suggestive, not proven, and S3 carries most of the absolute gain. Wrong if P3's `ilk2 report` shows no gain in minutes per accepted step; then revert the default. The time before the first edit barely moved, so the saving came from fewer exploratory turns and less thinking, not an earlier start.

## Findings that changed the design or the code

From `spikes/p1/findings.md`, numbered there:
1. **Claude Code's Bash tool runs commands in a new process group**, so killing the worker's group orphans them under SIGKILL. Termination now signals every descendant group, then sweeps processes whose cwd is in the worktree (matching on cwd, never argv), which also catches double-forked orphans.
2. **On macOS `killpg` on a zombie-only group is EPERM**, not ESRCH.
3. **A crashing hook fails open.** Claude Code treats any exit code other than 2 as non-blocking. Hooks turn every internal error into exit 2.
4. **The sandbox profile must allow Claude Code's own scratch** (`/private/tmp/claude-<uid>/<cwd key>`, `/private/tmp/claude-<hex>-cwd`). Without it every Bash call fails and "refused" means nothing.
5. **Setuid binaries cannot run under `sandbox-exec`** (`ps`). Gates therefore run outside the sandbox in the pinned environment, as designed. The brief tells the worker its own `ps`-based tests may fail.
6. **Resume is slow to its first event** (68-106 s against 16-31 s for a start, in step 1). Relevant to Q6.
7. Two test-design errors were caught and fixed before they could mislead: probe targets under the writable log dir (a vacuous pass), and the spike's virtualenv leaking into children's PATH.
